Google Drive 변경 감지 연동 매뉴얼

gd-poller가 전달하는 action, 파일 유형, 현재 경로와 이전 경로를 래퍼가 FlaskFarm으로 보냅니다. FlaskFarm은 이벤트를 먼저 DB에 저장한 뒤 rclone VFS와 BookOasis를 처리합니다.

1. gd-poller 설치 및 실행

gd-poller 설치 정보와 최신 소스는 공식 halfaider/gd-poller GitHub 저장소에서 확인할 수 있습니다.

먼저 gd-poller를 실행할 Python 환경에서 pip 설치 도구를 업데이트합니다.

Bash
python -m pip install --upgrade pip setuptools wheel

설치 또는 업데이트할 작업 경로로 이동한 뒤 아래 명령을 실행합니다. 현재 경로에 gd-poller 소스 폴더를 만들고 editable 방식으로 설치합니다.

Bash
pip install --src . -e "git+https://github.com/halfaider/gd-poller.git#egg=gd_poller"

FF 시스템 커맨드에 등록하거나 같은 Python 환경의 셸에서 다음 형식으로 실행합니다.

Bash
gd-poller /path/to/config.yaml

FF Docker 컨테이너 내부에 직접 설치한 패키지는 이미지를 다시 만들거나 컨테이너를 교체하면 사라질 수 있습니다. 재생성 후에도 유지하려면 커스텀 이미지 또는 컨테이너 시작 시 설치 절차를 별도로 구성해야 합니다.

2. Mate 사전 설정

  1. BookOasis Mate 설정에서 현재 DB 엔진과 연결 정보를 설정하고 BookOasis URL, 관리자 계정과 스캔 웹훅 토큰을 입력합니다. 개별 경로와 루트 스캔은 웹훅 토큰을 우선 사용하며, 구버전 호환 경로만 관리자 세션을 사용합니다.
  2. /api/webhook/scan의 path 요청을 지원하는 최신 BookOasis 사용을 권장합니다. SQLite는 사용할 일반·성인·오디오북·비디오북 DB 경로를 확인하고 MariaDB는 접속 정보를 입력합니다.
  3. 비디오북 변경은 MP4·MKV·AVI·WEBM·MOV·M4V·TS와 SMI·SRT·VTT 파일을 인식해 video 보관함의 경로 스캔으로 연결합니다.
  4. Google Drive 연동 설정에서 경로 매핑과 rclone VFS 규칙을 실제 컨테이너 경로에 맞춥니다.
  5. FlaskFarm 시스템 설정에서 전역 API 키를 확인합니다.
  6. gd-poller 컨테이너에서 래퍼 파일과 Python 3를 실행할 수 있어야 합니다.

3. gd-poller config.yaml 설정 예시

gd-poller config.yaml에 아래처럼 별도 poller를 추가합니다. 기존 poller에 결합할 때는 pollers[].dispatchers 목록에 CommandDispatcher 부분만 추가합니다. YAML 들여쓰기는 탭이 아닌 공백을 사용해야 합니다.

YAML
- name: '북오아시스 스캔용'
  polling_interval: 120
  page_size: 30
  ignore_folder: true
  patterns: [.*]
  targets:
    - 'GOOGLE_DRIVE_FOLDER_ID#/mnt/gds2/GDRIVE/READING'
  actions:
    - 'create'
    - 'move'
    - 'delete'
    - 'rename'
  dispatchers:
    - class: CommandDispatcher
      command: "python3 /data/plugins/bookoasis_mate/scripts/gd_poller_ff_bridge.py --url http://FLASKFARM_IP:9999/bookoasis_mate/api/gdrive_scan/event --apikey FLASKFARM_API_KEY"
      wait_for_process: true
      timeout: 15
#     mappings:
#       - "/GDRIVE:/mnt/gds2/GDRIVE"

CommandDispatcher는 명령 뒤에 action, file|directory, 현재 경로, 이전 경로를 순서대로 자동 추가합니다.

GOOGLE_DRIVE_FOLDER_ID, FLASKFARM_IP와 FLASKFARM_API_KEY를 실제 값으로 바꿉니다. 이 방식은 전용 Dispatcher가 추가되기 전까지 사용하는 임시 방식입니다.

주의: API 키가 gd-poller Command 로그와 운영체제 프로세스 목록에 노출될 수 있습니다. 설정 파일과 로그의 접근 권한을 제한하고 외부에 공유하지 마세요.

기본 60초 버퍼와 동일 보관함 중복 제거는 BookOasis Mate가 담당합니다. 같은 버퍼에 상위·하위 경로가 함께 들어오면 상위 경로 한 번으로 통합합니다.

4. 경로 매핑 원칙

gd-poller와 Mate 중 한쪽에서만 경로를 변환해야 합니다. 위 예시는 target의 # 뒤에 이미 /mnt/gds2/GDRIVE/READING을 사용하므로 gd-poller의 mappings는 주석 상태로 둡니다.

gd-poller CommandDispatcher는 target 경로를 만든 뒤 mappings의 원본 문자열을 단순 치환합니다. target이 이미 /mnt/gds2/GDRIVE/...인데 /GDRIVE:/mnt/gds2/GDRIVE를 함께 사용하면 아래처럼 접두사가 중복됩니다.

Path
/mnt/gds2/GDRIVE/READING/A.cbz
→ /mnt/gds2/mnt/gds2/GDRIVE/READING/A.cbz
  • gd-poller가 BookOasis DB 경로를 그대로 보내면 Mate 경로 매핑은 비웁니다.
  • gd-poller가 /GDRIVE/...처럼 축약 경로를 보내면 Mate에서 다음 형식으로 변환합니다.
Mapping
/GDRIVE => /mnt/gds/GDRIVE

gd-poller가 /GDRIVE/READING/만화/A.cbz를 보내면 /mnt/gds/GDRIVE/READING/만화/A.cbz로 해석합니다. 대상 접두사는 BookOasis DB의 libraries.physical_path에 저장된 보관함 경로와 같아야 하며 FlaskFarm 파일시스템에 실제로 존재할 필요는 없습니다.

gd-poller의 문법은 원본:대상이고 Mate의 문법은 원본 => 대상입니다. 두 설정을 동시에 사용하지 마세요.

Mate 연동 설정의 경로 매핑 검사에 실제 수신 예상 경로를 입력하면 Mate 변환 경로, BookOasis 보관함과 VFS 규칙을 저장 전에 확인할 수 있습니다.

Mate는 최종 경로에서 가장 길게 일치하는 보관함 루트를 제거해 보관함 기준 상대 디렉터리를 만듭니다. 예를 들어 보관함 루트가 /mnt/gds/GDRIVE/READING/만화이고 변경 파일이 .../만화/작품/A.cbz라면 BookOasis에는 작품을 전달합니다.

5. rclone VFS 규칙 예시

Config
/mnt/gds/GDRIVE|/GDRIVE|http://172.17.0.1:5572
/mnt/gds/GDRIVE|/GDRIVE|http://172.17.0.1:5572#vfs|RCLONE_USER|RCLONE_PASSWORD

인증정보가 필요하면 URL에 포함하지 말고 네 번째·다섯 번째 필드에 사용자명과 비밀번호를 입력합니다. 실제 값이 포함된 설정이나 로그는 외부에 공유하지 마세요.

BookOasis의 개별 경로 스캔이 현재 경로의 VFS 갱신을 수행하므로 Mate는 생성·수정·복원 시 별도 refresh를 보내지 않습니다. 이동·이름 변경·삭제는 사라진 이전 항목만 forget하여 같은 경로의 중복 VFS 갱신을 줄입니다.

개별 경로 스캔 동작과 주의 사항

  • Mate는 최신 토큰 기반 /api/webhook/scan의 path 계약을 우선 사용합니다. 지원되지 않으면 관리자 scan-path API를 사용하고, 두 경로 API가 모두 없는 구버전에서만 보관함 전체 웹훅으로 폴백합니다.
  • 파일 생성·수정·복원은 파일의 상위 폴더를, 폴더 생성·수정은 해당 폴더를 개별 경로 스캔합니다.
  • 파일 이동·이름 변경은 이전·현재 상위 폴더를 각각 처리합니다. 삭제된 폴더는 존재하지 않으므로 그 상위 폴더를 처리합니다.
  • 같은 버퍼 구간에 여러 파일이 변경되어도 동일 DB·보관함·상대 폴더의 개별 경로 스캔은 한 번만 보냅니다. 상위 폴더 스캔이 하위 폴더를 포함하면 하위 요청도 상위 요청에 합칩니다.
  • 보관함 루트 바로 아래의 파일 변경처럼 상대 폴더가 비어 있으면 scan-path를 호출할 수 없으므로 기존 웹훅으로 보관함 전체 비강제 증분 스캔을 요청합니다.
  • 인증 실패·일시적 네트워크 오류는 전체 보관함 스캔으로 전환하지 않고 이벤트 재시도 정책을 적용합니다.
  • 생성·수정·복원은 BookOasis 경로 스캔이 현재 VFS를 갱신하므로 Mate가 별도 refresh를 중복 호출하지 않습니다. 이동·이름 변경·삭제의 이전 항목 forget에 필요한 VFS 규칙이 없거나 호출에 실패하면 스캔을 보류하고 이벤트를 재시도합니다.
  • FlaskFarm이 재시작되면 처리 중이던 이벤트는 재시도 대기로 복구합니다.
  • 재시도는 이벤트를 받을 때 저장한 원본 경로에 현재 Mate 매핑 설정을 다시 적용합니다. gd-poller가 이미 중복된 경로를 보낸 기존 실패 이벤트는 원래 경로를 복원할 수 없으므로 삭제하고 새 이벤트를 받아야 합니다.
  • Mate는 합법적인 반복 디렉터리 이름을 훼손하지 않기 위해 중복 접두사를 자동 삭제하지 않습니다. 중복이 의심되면 원인과 설정 조치 방법을 오류로 표시합니다.
  • 지원 확장자가 아닌 파일 이벤트는 정상 응답 후 무시합니다. 디렉터리 이벤트와 스캔 범위를 변경하는 .bookoasisignore 파일 이벤트는 항상 처리합니다.
  • 처리 결과의 mode에는 path_webhook, admin_scan_path, full_webhook_fallback 중 실제 사용한 경로가 기록됩니다.
