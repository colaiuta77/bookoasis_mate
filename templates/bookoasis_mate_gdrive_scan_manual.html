변경 감지 흐름

Mate가 스캔 전에 VFS를 갱신합니다. 파일 확인 대기·스캔 요청 처리·DB 반영 확인은 서로 다른 단계이며, Discord는 별도 대기열에서 발송합니다. 도식은 로컬 소스 기준 안내이며 운영 서버의 실시간 상태를 표시하지 않습니다.

Google Drive 연동 매뉴얼

변경을 수집해 Mate 대기열에 저장하고 BookOasis에 개별 경로 스캔을 요청합니다. 입력 방식을 하나 선택하며, 대기열 이후의 처리 경로는 같습니다.

공통 설정에서 현재 DB 엔진과 연결 정보를 설정하고 BookOasis URL·관리자 계정·웹훅 토큰을 확인하세요. 일반·성인·오디오북·비디오 DB의 보관함에 연결할 수 있습니다.

기본 설정은 연동 사용·감지 방식·스캔 묶음·파일 확인·VFS·Discord, 연동 설정은 선택한 감지 방식의 연결·감시 경로, 고급 설정은 대기 한도·재시도·연결 제한·이력 보관을 다룹니다. 탭을 바꾸어도 같은 설정 폼의 입력값을 함께 저장합니다. Activity 조회 지연과 Discord 묶음 시간은 해당 기능 안의 접기 영역에 있습니다.

1. Mate 자체 감지 시작

  1. 기본 설정의 변경 감지 방식에서 Mate 자체 감지를 선택합니다.
  2. 연동 설정에서 FF가 실행할 수 있는 rclone 경로와 /data/rclone.conf를 함께 입력합니다. 버전 확인·설정 확인으로 확인합니다. 둘 다 비우면 FF rclone 플러그인 설정을 사용합니다.
  3. 리모트·실제 폴더 ID·리모트 상대 경로·BookOasis 경로 루트를 등록합니다. 감시 경로는 최대 10개이며 동일 폴더 ID·중첩 경로는 등록할 수 없습니다.
  4. 각 경로에서 Changes 또는 Activity를 선택합니다. Union은 실제 감시할 직접 Drive upstream을 추가로 선택합니다.
  5. 설정 저장 → 토큰 갱신 및 연결 테스트를 실행합니다. 기본 설정의 VFS 규칙·필요한 파일 확인 경로 매핑을 확인한 뒤 연동 사용을 켜서 저장합니다. 외부 gd-poller용 경로 매핑은 자체 감지에 적용하지 않습니다.

최초 실행은 전체 재귀 목록 조회를 실행하지 않고 현재 시점부터 시작합니다. 기존 파일 전체를 스캔하거나 과거 변경을 복구하는 기능이 아닙니다.

rclone.conf는 부모 디렉터리까지 쓰기 가능하고 영구 저장되는 곳에 두세요. 파일 하나만 bind mount하면 토큰 저장 시 교체에 실패할 수 있습니다. GDS와 저장 경쟁을 피하려면 Mate 전용 사본을 사용하고 양방향 자동 동기화하지 마세요.

직접 경로를 사용하면 FF rclone 플러그인은 필수가 아닙니다. 중첩 Union·crypt·로컬 upstream은 자동 해석하지 않습니다.

  • Activity는 OAuth 프로젝트에서 Drive Activity API를 활성화하고 두 권한으로 재인증해야 합니다. scope 문자열만 바꾸어도 기존 토큰에 권한이 추가되지는 않습니다.
  • Activity에는 바로가기 ID가 아닌 실제 대상 폴더 ID를 입력합니다. 하위 바로가기의 대상 내부는 자동 감시하지 않습니다.
  • 처음 관측한 파일이나 비교 정보가 없는 파일은 Changes에서도 한 번 보수적으로 처리할 수 있습니다. 수정 날짜만으로 대량 이벤트가 모두 오탐이라고 단정하지 마세요.
  • Activity는 5분보다 늦게 공개되거나 계정에 보이지 않는 활동을 놓칠 수 있습니다. 휴지통 파일도 부모 정보로 감시 폴더 안의 경로가 확인되면 삭제 이벤트로 처리합니다. 파일을 복구하지는 않습니다.
  • 개별 파일의 경로를 복원할 수 없으면 실패 목록에 경로 확인 보류로 남기고 다음 활동을 수집합니다. JSON에서 파일 ID·동작·사유를 확인한 뒤 경로 수정으로 재시도하세요. 인증·호출 제한·서버 오류나 DB 저장 실패는 체크포인트를 유지합니다.
  • 체크포인트는 방식별로 분리됩니다. 방식 전환 전에 생성된 대기 이벤트는 남으므로 전환 시 중복 수집 가능성을 확인하세요.
토큰 갱신·재인증

액세스 토큰 만료 또는 API 401이면 Mate가 OAuth 토큰을 갱신·저장한 뒤 한 번 재시도합니다. invalid_grant는 리모트 재인증이 필요합니다.

docker exec -it flaskfarm /usr/bin/rclone --config /data/rclone.conf config reconnect gds2:

gds2는 실제 리모트 이름으로 바꾸세요. rclone 명령과 Google API 요청에는 각각 설정한 제한 시간이 적용됩니다.

설정 확인 팝업은 access_token·refresh_token·client_secret을 원문으로 표시합니다. 화면을 공유하지 마세요.

3. 경로 매핑·VFS

VFS는 기본 설정 탭에서 세 감지 방식에 공통으로 설정합니다. rclone vfs/refresh 사용은 기본 On이며, Off이면 Mate의 사전 forget·refresh를 생략합니다. 이때 캐시 갱신은 외부에서 보장해야 합니다.

변경 이벤트 목록의 시간은 최근 시도 기준입니다. 처리 완료는 Mate의 이벤트 처리 종료이며, 비동기 스캔 요청의 실제 완료를 의미하지 않습니다. 과거 이벤트에 기록되지 않은 처리 시작·스캔 요청 시각은 빈 값으로 표시합니다.

이벤트 경로를 BookOasis DB의 보관함 경로에 맞춥니다. 이미 같으면 매핑은 비웁니다. gd-poller와 Mate 양쪽에서 중복 변환하지 마세요.

/GDRIVE|/mnt/gds/GDRIVE

외부 입력용 매핑과 파일 확인용 매핑은 모두 왼쪽 경로|오른쪽 경로 형식입니다. 이전에 저장한 => 형식도 계속 읽으며, 설정 화면에서는 |로 표시합니다. 외부 입력용 매핑은 gd-poller 경로를 BookOasis 경로로, 파일 확인용 매핑은 BookOasis 경로를 FlaskFarm에서 보이는 경로로 변환합니다.

외부 연동의 경로 매핑 검사에서 실제 수신 예상 경로를 넣고 변환 결과·보관함·VFS 규칙을 확인합니다. 자동 제안은 한 보관함에 명확히 대응할 때만 사용하며 | 형식으로 입력합니다. 활성 VFS 규칙이 하나이면 그 경로 쌍도 함께 맞추고 RC 주소·VFS 이름·인증값은 유지합니다. 적용 후 설정 저장으로 확정하세요.

BookOasis 경로 루트는 DB 기준이며 FF에 같은 미디어 마운트가 없어도 됩니다. rclone 실행 파일·설정 파일은 FF에 있어야 합니다.

스캔에는 보관함 기준 상대 디렉터리를 사용합니다. 보관함이 /books이고 파일이 /books/작품/A.cbz이면 작품을 전달합니다.

VFS 규칙 예시 
/mnt/gds/GDRIVE|/GDRIVE|http://RCLONE_HOST:5572
/mnt/gds/GDRIVE|/GDRIVE|http://RCLONE_HOST:5572#vfs|RCLONE_USER|RCLONE_PASSWORD

형식은 BookOasis 경로 접두사 | rclone 경로 | RC 주소 | 사용자명 | 비밀번호입니다. 인증정보는 URL에 넣지 마세요.

자체 감지와 외부 연동 모두 VFS 규칙이 필요합니다. Mate는 이동·이름 변경·삭제 시 이전 항목을 forget하고, 스캔 전에 부모 폴더 목록을 refresh합니다. BookOasis는 VFS 갱신보다 먼저 경로 존재 여부를 검사할 수 있습니다.

삭제·이동 이전 경로가 없다는 응답이면 해당 보관함 안의 상위 폴더를 재요청합니다. 루트까지 올라가면 해당 보관함의 증분 스캔을 요청합니다. 생성 경로의 404나 인증·통신 오류에는 이 처리를 하지 않습니다.

rclone.conf만으로 RC 주소를 알아낼 수는 없습니다. 규칙이 없거나 VFS 갱신이 실패하면 스캔을 보류합니다.

VFS 경로 자동 감지는 규칙에 입력한 RC의 활성 VFS와 경로 후보를 읽기 전용으로 검사합니다. 폴더 존재만 확인하므로 같은 이름의 다른 폴더일 수도 있습니다. 실제 마운트 경로를 확인하고 이 후보 적용 → 설정 저장으로 확정하세요. RC에 활성 VFS가 없거나 경로가 다르면 수동 규칙을 사용합니다. 최대 64개 후보·약 20초를 검사하며 마지막 HTTP 요청의 제한 시간만큼 더 걸릴 수 있습니다.

4. 스캔 처리·오류 확인

  • 같은 부모 폴더의 마지막 변경부터 기본 60초를 기다린 뒤 최대 500개 이벤트를 한 배치로 처리합니다. 변경이 계속되어도 각 이벤트는 최대 버퍼 대기(기본 600초) 후 처리합니다. 0초 버퍼는 즉시 처리하며, 같은 DB·보관함·상대 폴더와 겹치는 상위 경로는 합칩니다.
  • 파일 확인 대기는 기본 0초(미사용)입니다. 사용하려면 BookOasis 경로 → FlaskFarm에서 보이는 경로를 명시적으로 매핑하세요. 추가·수정은 존재, 삭제는 부재, 이동·이름 변경은 새 경로 존재와 이전 경로 부재를 확인합니다. 파일 내용·크기 안정화·업로드 완료를 확인하는 기능은 아닙니다. 접근 불가 루트는 삭제 성공으로 처리하지 않습니다.
  • 파일 대기는 스캔 전에 VFS 갱신 후 시작하며, 기본 20초마다 재확인합니다. 대기 상태·시작 시각은 DB에 남고 재시작 후에도 유지됩니다. 다른 폴더의 처리를 막지 않고 실패 횟수를 소모하지 않습니다. 제한 시간을 넘으면 실패로 표시하고 수동 재시도 시 새 대기를 시작합니다.
  • 자체 감지의 과거 Drive 활동은 현재 ID 상태와 대조합니다. 수집 시 이미 복원된 항목은 현재 상태 이벤트로 전환하고 원본 액션·사유를 JSON의 drive에 남깁니다. 파일 확인에서 막힌 경로는 원본 ID와 현재 부모 목록의 유일한 ID를 비교하며, 복원·교체가 확인되면 부재 대기 대신 기존 상위 폴더 스캔으로 진행합니다. 판단 상세는 JSON의 reconciliation에 기록합니다. ID가 없거나 API·마운트 접근에 실패하면 기존 대기를 유지하며, 조회 실패 종류는 reconciliation_error에 남깁니다. 동일 경로 재동기화는 DB 경로만으로 내용 갱신을 증명할 수 없어 자동 확인 미지원으로 기록합니다.
  • VFS forget·refresh는 동일 규칙·인증별로 최대 64개 경로를 묶습니다. 삭제 경로 처리를 먼저 실행하며 경로별 갱신 실패가 있는 스캔은 보류합니다. 갱신 묶음의 응답 시간이 초과되면 개별 경로로 나누어 재확인합니다. 자체 감지는 한 수집 회차에서 같은 인증·조회 조건의 Drive GET 응답과 인증 정보를 공유합니다. Activity 조회와 스캔 실행 요청은 캐시하지 않습니다.
  • 관리자 계정이 있으면 관리자 경로 스캔을 우선 사용합니다. 계정이 없거나 404/405이면 토큰 기반 경로 웹훅을 사용합니다.
  • 파일은 상위 폴더, 폴더는 해당 경로를 스캔합니다. 이동은 이전·현재 경로, 삭제된 폴더는 상위 폴더를 처리합니다.
  • 다중 루트 보관함은 관리자 scan-path API에 보관함 내부의 절대 경로를 전달하여 해당 경로만 스캔합니다. 관리자 계정이나 API가 없으면 오류를 표시하며 자동으로 전체 스캔하지 않습니다.
  • 단일 보관함 루트 변경 또는 삭제 경로의 상위 폴더도 없을 때는 보관함 전체 증분 스캔으로 전환하며 사유를 표시합니다. 강제 전체 재분석은 아닙니다. 요청 접수는 실제 스캔 완료와 구분됩니다.
  • DB 경로 반영 확인은 새로 처리한 일반·성인 도서 파일 이벤트에 적용됩니다. 요청 처리 후 이벤트별 20초 간격·10분 대기 한도로 BookOasis DB를 읽기 전용으로 확인합니다. 기존 스캔 작업자가 확인하므로 긴 스캔 배치 실행 중이거나 작업 중지 상태에서는 확인과 시간 초과 표시가 늦어질 수 있습니다. 추가·복원은 현재 활성 경로, 이동·이름 변경은 새 활성 경로와 이전 활성 경로 부재, 삭제는 활성 경로 부재를 확인합니다. DB 확인 대기는 Mate 재시작 후 이어집니다.
  • 확인 시간 초과는 스캔 실패를 뜻하지 않으며 자동 재스캔이나 DB 수정을 하지 않습니다. 파일 수정·폴더·보조 파일·오디오/비디오는 경로만으로 판단할 수 없어 JSON에 자동 확인 미지원으로 기록합니다. 목록에는 확인된 경우 반영 확인 시각만 표시하며, 확인 대기·시간 초과 문구는 유지합니다. 반영 확인은 관측한 DB 경로 상태이며 전체 스캔·메타데이터·표지 갱신 완료를 보장하지 않습니다. 상세 판정과 사유는 JSON의 db_verification에서 확인하세요. 과거 처리 이력은 소급 확인하지 않으며 Discord는 기존 요청 처리 알림을 유지합니다.
  • 시간 초과·연결 단절·408/502/503/504 등 완료 여부가 불명확한 경로 스캔은 자동 재시도하지 않습니다. BookOasis 결과·로그 확인 후 수동 재시도하세요.
  • 목록의 삭제 이벤트는 삭제 경로 하나만 표시하며 이동 전은 이동·이름 변경에만 표시합니다. 실패 상세는 JSON에서 확인합니다. 잘못된 원본 경로는 경로 수정 후 재시도합니다. 일반 재시도는 현재 매핑을 다시 적용합니다.
  • 지원하지 않는 확장자는 무시합니다. 디렉터리와 .bookoasisignore 이벤트는 항상 처리합니다.

Google 호출 제한은 약 60초부터 최대 15분까지 대기 시간을 늘려 재시도합니다. 여러 서버가 같은 계정·프로젝트를 쓰면 할당량을 공유할 수 있습니다. MariaDB 1205는 DB 잠금 대기 오류이므로 스캐너·메타데이터 작업과 DB 로그를 함께 확인하세요.

JSON의 스캔 mode
  • admin_scan_path·path_webhook — 변경된 폴더만 스캔.
  • library·full_webhook_compat — 보관함 전체 증분 스캔.
  • full_webhook_fallback — 과거 버전의 전체 스캔 대체 이력. 현재는 추가 호출하지 않습니다.
  • path·unknown — 내부·예외 표시. 실제 요청·오류를 함께 확인하세요.

5. 작업 중지·대기열 삭제

  1. 작업 중지를 누릅니다. 연동 사용이 꺼지고 현재 요청 결과를 저장한 뒤 다음 요청부터 멈춥니다.
  2. 중지 요청 중이 중지로 바뀔 때까지 기다립니다. 요청 제한 시간까지 걸릴 수 있습니다.
  3. 필요하면 대기·재시도 이벤트 일괄 삭제를 실행합니다. 검색 조건과 관계없이 해당 상태의 모든 이벤트를 삭제하며 복구할 수 없습니다.
  4. 재개하려면 연동 사용을 켜고 저장합니다. 작업자 깨우기만으로 연동 사용이 켜지지는 않습니다.

완료 결과와 체크포인트는 보존합니다. 미처리 이벤트는 시도 횟수를 소모하지 않고 재시도 대기로 돌아갑니다. 일부 대상만 스캔한 이벤트는 중복 방지를 위해 수동 확인 대상으로 남습니다.

이미 BookOasis에 전달한 스캔은 취소하지 않습니다. 체크포인트 초기화는 대기열 삭제가 아니며 아직 읽지 않은 변경을 건너뜁니다. 강제 재시작으로 처리 중 이벤트를 복구하면 이미 전달된 요청이 다시 실행될 수 있습니다.

이벤트 API

/bookoasis_mate/api/gdrive_scan/event — 외부 수신 전용. FlaskFarm 전역 API 키가 필요합니다.

외부 gd-poller 설치·설정

설치 환경은 gd-poller 공식 저장소를 확인하세요. 아래 래퍼 경로는 gd-poller가 실행되는 환경에서 보여야 합니다.

python -m pip install --upgrade pip setuptools wheel
pip install --src . -e "git+https://github.com/halfaider/gd-poller.git#egg=gd_poller"
gd-poller /path/to/config.yaml

기존 pollers[].dispatchers에 아래 둘 중 하나만 추가합니다. YAML은 탭이 아닌 공백을 사용합니다.

YAML
- class: WebhookDispatcher
  url: "http://FLASKFARM_IP:9999/bookoasis_mate/api/gdrive_scan/event?apikey=FLASKFARM_API_KEY"
  method: "POST"
  payload:
    action: "{action}"
    path: "{path}"
    removed_path: "{removed_path}"
    is_folder: "{is_folder}"
  timeout: 15.0

WebhookDispatcher를 지원하는 설치본에서 사용합니다. Mate는 JSON의 is_folder를 파일·폴더로 해석합니다.

YAML
- class: CommandDispatcher
  command: "python3 /data/plugins/bookoasis_mate/scripts/gd_poller_ff_bridge.py --url http://FLASKFARM_IP:9999/bookoasis_mate/api/gdrive_scan/event --apikey FLASKFARM_API_KEY"
  wait_for_process: true
  timeout: 15

poller의 감시 폴더·경로·actions도 설정하세요. 수정·복원을 받으려면 edit·restore를 포함합니다. 명령 뒤의 action·파일 유형·현재/이전 경로는 Dispatcher가 추가합니다.

명령행 키는 로그·프로세스 목록에 노출될 수 있고, 웹훅 URL의 키도 오류·프록시 로그에 남을 수 있습니다. 외부 구간은 HTTPS를 사용하고 설정·로그 접근을 제한하세요.

Discord 알림 대기열

Mate 자체 감지는 감시 대상별 첫 실제 오류와 이후 실제 수집 성공에 따른 복구를 알립니다. 반복 오류·재시작·사용자 중지·호출 제한 대기는 새 상태 전환으로 보지 않습니다. 이 알림은 묶음 대기 없이 처리하되 웹훅의 호출 제한은 따릅니다. 외부 입력 방식의 송신자 상태는 추정하지 않습니다.

최종 처리 결과를 DB에 보존하고 스캔과 독립된 작업자가 기본 60초 동안 묶어 발송합니다. 새 결과가 계속 들어와도 최초 결과부터 최대 180초 후 발송하며, 묶음 시간을 0으로 설정하면 추가 지연 없이 다음 작업자 실행에서 처리합니다. 0초여도 그 사이 쌓인 결과는 함께 보낼 수 있습니다. 실패 항목을 먼저 표시하고 같은 원본 Activity·대상·시각의 알림은 대응하는 primary 동작이 확인될 때 대표 카드로 묶되 실패 카드는 별도로 보존합니다.

대표 카드는 생략하지 않고 메시지당 최대 10개 및 전체 카드 문자 한도에 맞춰 여러 메시지로 나누어 보냅니다. 단일 카드가 문자 예산을 넘으면 긴 필드를 줄여 표시합니다. 성공한 조각의 진행 위치를 DB에 저장하며 재시작·재시도 시 아직 성공하지 않은 조각부터 이어서 처리합니다. 원본 개별 결과는 변경 이벤트 목록·JSON에서 확인하세요.

HTTP 413은 현재 미발송 조각을 카드 경계로 더 작게 나누어 재시도합니다. 단일 카드도 413으로 거절되면 해당 묶음을 명시적인 최종 실패로 남기며 전체 발송 완료로 처리하지 않습니다. 이 상태 코드만으로 문자 한도·프록시·Discord 측 거절 중 어느 원인인지 단정할 수 없습니다.

429 호출 제한은 Discord가 알려 준 시간 동안 해당 웹훅 전체를 기다립니다. 연결 오류·5xx는 30초부터 최대 30분 간격으로 재시도하며 10회 실패하면 종료합니다. 401·403·404는 목적지 발송을 차단합니다. 웹훅을 확인하고 다시 저장하면 차단이 해제되며 이전 실패 알림은 자동 재발송하지 않습니다.

웹훅 저장·삭제 시 기존 미발송 알림을 취소합니다. 이미 진행 중인 HTTP 요청은 소급 취소할 수 없습니다. 플러그인 재시작 시 대기열을 복구하며 Drive 작업 중지만으로 기존 알림 대기열을 삭제하지 않습니다. 완료·취소·최종 발송 실패는 7일 후 정리합니다.

알림 대기열 기록만 실패하면 이벤트에 ‘스캔 결과 확인됨 · 알림 기록 재시도 대기’를 표시하고 저장을 재시도합니다. 이 상태는 재시작 후에도 스캔 요청을 다시 보내지 않습니다.

실제 메시지 생성 응답을 확인하지만, Discord가 수신한 직후 연결이나 프로세스가 끊기면 재전송으로 중복될 수 있습니다. 알림의 ‘요청 접수’는 코어의 실제 스캔 완료를 보장하지 않습니다. 알림 전송 실패가 스캔을 다시 실행하지는 않으나, 스캔 결과 자체를 저장할 수 없는 전체 DB 장애까지 정확히 한 번 실행을 보장하지는 않습니다.
