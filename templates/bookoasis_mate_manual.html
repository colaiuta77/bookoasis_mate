BookOasis Mate 매뉴얼

모든 기능에 공통으로 적용되는 연결 조건, 필수 패키지, 파일 권한과 안전 수칙을 안내합니다. 기능별 세부 절차는 각 메뉴의 매뉴얼을 확인하세요.

로컬 디스크·Windows Docker·CIFS/NFS·FUSE 감지는 로컬 폴더 감지 메뉴에서 설정합니다. 감시 프로세스는 FlaskFarm과 같은 Python 환경을 사용하며 Linux 실시간 감지에는 watchdog>=4,<7이 필요합니다.

Mate 전체 구조

처음 연결하기

  1. 설정에서 BookOasis URL과 DB 엔진을 선택합니다. SQLite는 DB 파일 경로, MariaDB는 접속 정보를 입력합니다.
  2. 관리자 API를 사용할 계정과 BookOasis WEBHOOK_TOKEN을 입력하고 연결을 확인합니다.
  3. 표지·로그·플러그인·폰트 경로는 FlaskFarm 컨테이너에서 보이는 경로로 지정합니다. Google Drive 감시의 BookOasis 경로 루트는 BookOasis DB 경로를 따릅니다.
  4. 필요한 기능만 설정한 뒤 해당 메뉴에서 실행합니다. 진단 조회와 실제 삭제·이관·스캔 요청은 별도 작업입니다.

자동 감지는 DB_ENGINE·DBMS와 설정을 확인합니다. MariaDB 연결 실패 시 SQLite로 자동 전환하지 않습니다.

연결·표지 경로 확인

  • DB 엔진 불일치가 확인되면 이관과 고아 표지 정리를 차단합니다. 엔진이 같아도 같은 서버·DB인지 직접 확인해야 합니다.
  • 원격 COVER_STORAGE_ROOT와 Mate 표지 경로가 다르면 같은 저장소의 마운트인지 확인하고 원격 커버 경로 확인값을 입력합니다. 원격 기본 경로는 <default>로 확인합니다.
  • 커버 이동 중이거나 경로 확인값이 맞지 않으면 관련 검사·정리·이관을 차단합니다. 검사 중 원격 설정을 바꾸지 마세요.
  • 서버 중지·구버전·인증 실패로 원격 확인이 불가능할 때는 경고가 표시됩니다. 경고는 안전이 확인됐다는 뜻이 아닙니다.

MariaDB 준비

설정 → DB 연결 → MariaDB 필수 구성요소에서 확인·설치합니다.

  • PyMySQL>=1.1,<2 — DB 연결·조회.
  • mariadb-client — 이관 시 논리 백업·복원. mariadb-dump·mariadb 또는 호환 클라이언트가 필요합니다.

호스트는 FF 컨테이너에서 접근 가능한 주소입니다. 별도 컨테이너의 MariaDB에 연결할 때 127.0.0.1은 FF 자신을 가리킵니다. DB 계정의 Host 허용 범위에 실제 접속 원본 IP가 포함되어야 합니다.

진단에는 각 미디어 DB 읽기 권한이, 실제 이관에는 대상 DB 쓰기·백업·복원 권한이 필요합니다. 읽기 풀은 DB마다 생성되므로 총 연결 수를 고려하세요. 풀 크기 변경은 저장 후 다음 조회부터 적용됩니다.

컨테이너에 직접 설치한 패키지는 재생성 때 사라질 수 있습니다. 계속 사용할 패키지는 사용 중인 FF 이미지에 맞춘 사용자 이미지에 포함하세요.

SQL 도구

  1. SQL 모드·대상 DB·진단 프리셋을 선택합니다.
  2. 최대 결과와 제한 시간을 정하고 실행합니다.
  3. 잘림 표시와 오류를 확인합니다. 행 제한만으로 전체 쿼리 비용이 줄지는 않습니다.

일반 조회는 최대 500행·10초, MariaDB 관리자 진단은 최대 5,000행·30초입니다. SELECT·WITH·EXPLAIN 한 문장만 허용하며 쓰기·파일 출력·민감 설정 조회는 차단합니다.

관리자 진단은 허용된 information_schema·performance_schema 테이블만 조회합니다. InnoDB 트랜잭션은 PROCESS 권한이 필요할 수 있습니다. 권한을 자동 부여하지 않으며, 실행 중 SQL 본문에는 민감한 값이 포함될 수 있습니다.

플러그인 관리

  • 플러그인 탭에서 설치된 항목을 먼저, 미설치 항목을 뒤에 표시합니다. 전체·활성화·비활성화·설치됨·미설치로 필터링합니다.
  • 업데이트 확인은 버전을, Topic 새로고침은 발견 목록을 갱신합니다. 전체 새로고침은 저장소 접근 상태도 확인합니다.
  • 사용자 저장소와 비공개 Gitea는 설정 탭에서 등록합니다. 저장소·ZIP 설치는 패키지 검사 후 확인을 거쳐 실행합니다.
  • 일반 설정은 BookOasis가 제공한 설정 계약으로 편집합니다. BookOasis 전용 설정은 BookOasis에서 열어 변경합니다. 비밀번호·토큰은 비우면 유지하고 삭제를 선택해야 초기화됩니다.
  • 설치 진행은 상단에 표시하며 성공 후 숨깁니다. 상세 내역은 작업 이력에서 확인합니다.

실행 상태 미확인은 비활성화와 다릅니다. 관리자 API 연결을 먼저 확인하세요. 저장소 404 항목은 미설치 목록에서 숨길 수 있지만 설치 파일과 사용자 등록 원본은 삭제하지 않습니다.

플러그인은 BookOasis 서버에서 실행되는 코드입니다. 소유자·소스를 신뢰하는 패키지만 설치하세요.

Gitea 연결 오류

연결 검사는 /api/v1/user의 사용자 인증을 확인합니다. 성공해도 모든 비공개 저장소의 읽기 권한을 보장하지 않습니다. 사용자 조회와 대상 저장소 읽기가 가능한 토큰을 사용하세요.

  • 401 인증 실패 — 토큰 만료·폐기, 서버 주소, 프록시의 Authorization 헤더 전달을 확인합니다.
  • 403 접근 거부 — 사용자 조회 또는 저장소 읽기 권한을 확인합니다. 프록시 접근 정책도 원인일 수 있습니다.
  • 404 — 연결 검사에서는 API 주소·프록시 경로를, 저장소 조회에서는 이름·ref·접근 권한을 확인합니다.
  • 429·5xx — 요청 제한 또는 서버·프록시 오류입니다. 잠시 후 재시도하고 서버 상태를 확인합니다.
  • DNS·SSL·시간 초과·연결 실패 — FF 컨테이너의 DNS, 인증서·TLS, 주소·포트·방화벽을 확인합니다. 인증서 검증을 끄기보다 인증서 구성을 바로잡으세요.

Docker·폰트

  • Docker 관리는 FF의 /host 마운트와 호스트 Docker·Compose 접근이 필요합니다. 작업 대상은 bookoasis 서비스입니다.
  • 재시작은 기존 컨테이너를 다시 시작하고, 구성 적용은 Compose 변경을 반영합니다. 이미지 방식은 이미지를 내려받고, 소스 빌드 방식은 Git 업데이트 후 빌드합니다.
  • 소스 수정 파일이 있으면 자동 업데이트를 중단합니다. 변경 이유를 확인하고 백업한 뒤 Git 상태를 정리하세요. 변경 내용을 강제로 지우지 마세요.
  • 폰트는 FF 업로드 폴더와 BookOasis /app/static/fonts/custom이 같은 저장소를 보게 합니다. TTF·OTF·WOFF·WOFF2, 파일당 최대 30MB이며 같은 이름은 덮어쓰지 않습니다.
  • 폰트 마운트 변경은 컨테이너 재생성 등 Compose 구성 적용이 필요합니다. 기존 마운트에 파일만 추가하면 폰트 목록을 다시 조회합니다. 업로드 자체는 재시작하지 않습니다.

삭제·이관 전 확인

  • DB와 표지를 별도로 백업하고, 대상 DB·경로를 확인합니다.
  • Kavita·통DB 이관과 고아 표지 정리는 Dry Run을 먼저 실행합니다. 카테고리 이관은 별도 Dry Run이 없으므로 패키지 검사와 백업을 확인합니다.
  • 실제 DB 변경·교체 중에는 BookOasis와 스캐너 등 같은 데이터를 쓰는 작업을 중지합니다.
  • 토큰·비밀번호·개인정보가 담긴 설정, 로그, DB 패키지를 외부에 공유하지 마세요.

외부 계약은 BookOasis API 문서와 설치한 BookOasis 버전을 함께 확인하세요.
