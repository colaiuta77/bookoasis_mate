로컬 폴더 감지

로컬 디스크는 실시간, Windows Docker·CIFS/NFS·FUSE는 폴링으로 확인합니다. 매뉴얼

감시 경로

두 경로 모두 각 컨테이너에서 보이는 절대 경로입니다. 설정 변경은 작업 중지 후 적용하세요.

기본 200,000 · 최대 1,200,000. 권수가 아니라 감시 확장자 파일과 폴더 합계입니다. 제외 패턴·비대상 파일은 집계하지 않습니다. 60만 권도 폴더·메타데이터를 더하면 한도를 넘을 수 있습니다. 높일수록 최초·정기 전체 조회의 시간과 메모리가 늘어납니다. 작업 중지 후 저장하고 새 기준으로 시작하세요.
한 줄에 하나씩 입력합니다. 끝에 /를 붙이면 폴더와 하위 전체를 제외합니다. *.tmp 같은 파일 패턴도 지원하며, 비우면 제외하지 않습니다. 작업 중지 → 설정 저장 → 새 기준으로 시작 순서로 적용하세요.
로컬 폴더 변경 처리 알림 전용입니다. 비워 두면 보내지 않으며 Google Drive 알림 주소는 사용하지 않습니다.

BookOasis 연결은 기존 Mate 설정을 사용합니다. Google Drive 연동을 켤 필요는 없습니다.

감지 작업자 실행 중 매시간 완료·최종 실패 기록을 정리합니다. 대기·재시도·처리 중 기록과 실제 파일은 유지합니다.

실시간 감지 구성요소

현재 FlaskFarm Python에 watchdog>=4,<7을 설치합니다. 폴링에는 필요하지 않습니다. 컨테이너 재생성 시 재설치가 필요할 수 있습니다.

사용 매뉴얼

  
    
    
  1. 감시 폴더를 FlaskFarm 컨테이너에 마운트하고, 동일 자료를 BookOasis 보관함에도 연결합니다.
    2. 
    
  2. Mate 경로와 BookOasis 경로를 입력합니다. 예를 들어 /watch/books → /data/books입니다.
    3. 
    
  3. Linux 실제 디스크는 자동 또는 실시간, Windows Docker·SMB/CIFS·NFS·FUSE는 폴링을 선택합니다.
    4. 
    
  4. 이어서 시작은 저장된 기준과 현재 상태를 전체 비교해 중지 중 변경을 수집합니다. 기준이 없는 최초 실행은 기존 파일을 스캔하지 않고 기준만 저장합니다. 감지가 활성화된 채 재시작하면 자동으로 이어서 시작합니다.
    5. 
    
  5. 새 기준으로 시작은 성공한 전체 수집 후 기준을 교체하며 중지 중 변경을 스캔하지 않습니다. 감시 기준은 Mate DB 옆 bookoasis_mate_local_baseline.db에 저장하므로 해당 데이터 볼륨을 유지하세요. 이벤트 기록 자동 삭제와 별개입니다.
    6. 
    
  6. 재시작에도 전체 파일 확인과 inotify 재등록은 필요합니다. 경로 매핑·제외 패턴·확장자 또는 루트 식별 정보가 바뀌면 이어서 시작을 보류합니다. 마운트를 확인하고 필요하면 수동 스캔 후 새 기준으로 시작하세요. 큐 저장 후 기준 저장 전에 종료되면 일부 이벤트가 재전달될 수 있습니다.
    7. 
  

  
    
    
  • 감지 제외 패턴은 Mate의 신규 이벤트 수집에 적용하며 기존 기록·대기열은 지우지 않습니다. BookOasis 스캔 제외 설정과 별개입니다. / 없는 패턴은 모든 깊이의 이름, / 포함 패턴은 감시 루트 기준 상대 경로에 대소문자를 구분하여 적용합니다. *, ?, []를 지원하며 #은 주석이 아닙니다. 폴더 제외 시 스냅샷 하위 탐색도 생략합니다.
    • 
    
  • 실시간 감지에는 FlaskFarm Python 환경의 watchdog>=4,<7 설치가 필요합니다. 작업 중지 후 설정의 구성요소 설치 버튼을 사용하세요. 설치 완료 후 새 기준으로 시작합니다.
    • 
    
  • 실시간 모드는 최초 전체 수집 후 변경된 파일·폴더 범위만 비교합니다. 신호 누락 보완을 위해 1시간마다, 변경 경로가 1만 개를 넘으면 전체 비교합니다. 폴링은 매 주기 전체 비교합니다. 큰 폴더 이동·삭제는 해당 하위 기준을 대조하며 대량 삭제 보호를 유지합니다.
    • 
    
  • 한도는 경로당 기본 20만·최대 120만 대상 파일+폴더입니다. 비대상 확장자는 기준에서 제외하되 .bookoasisignore는 포함합니다. 최초·전체 비교 시 이전/현재 기준 메모리와 디스크 조회 비용이 필요합니다. Linux inotify 감시 한도는 별개이며 폴더 수가 많으면 OS 한도 오류가 날 수 있습니다. Mate가 OS 설정을 자동 변경하지 않습니다.
    • 
    
  • 이동은 삭제+생성으로 기록합니다. 심볼릭 링크는 따라가지 않습니다. 감시 중지·재시작 사이의 변경은 자동 복구하지 않습니다.
    • 
    
  • 루트 변경·조회 오류·빈 트리·대량 삭제는 기준을 유지하고 보류합니다. 정상 삭제임을 확인했다면 BookOasis 수동 스캔 후 중지·시작으로 새 기준을 만드세요.
    • 
    
  • 같은 경로의 네이티브 플러그인·gd-poller 감시는 직접 꺼 주세요. Mate 내 Drive 자체 감지와 겹치는 대상은 시작할 수 없습니다.
    • 
    
  • 로컬 스캔은 rclone VFS를 갱신하지 않습니다. FUSE 캐시에 아직 보이지 않는 변경은 감지할 수 없습니다.
    • 
    
  • 중지 시 감지는 종료하고 현재 API 요청 이후 스캔을 멈춥니다. 대기열은 유지되며 별도로 삭제할 수 있습니다. 자동 삭제와 보관 기간은 설정에서 변경하며 기본은 On·30일입니다. 개별 삭제는 완료·최종 실패 기록에만 적용합니다.
    • 
    
  • 요청 완료는 BookOasis가 스캔 요청을 수락했다는 뜻입니다. 최종 스캔 완료 여부는 BookOasis에서 확인하세요.
    • 
    
  • Windows 네이티브 FlaskFarm 실행은 지원 범위 밖입니다. Windows PC 공유 폴더는 NAS/컨테이너에 CIFS로 마운트해야 합니다.
